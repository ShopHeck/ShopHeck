# Engineering Audit — Correctness, Performance, Test Coverage

**Scope (Aug 2026):** all of `src/`, `netlify/functions/`, and the build config,
audited for *data correctness, runtime performance, and test coverage*.

This audit deliberately does **not** re-tread `docs/ux-audit.md`, which is
current and covers the paywall, onboarding, retention, navigation,
accessibility and visual identity — including open items this document does not
duplicate (Coach Pro's `coach_notes` sync, the double iOS paywall, three
unsynchronized Bluetooth connections, two missing delete confirmations). Read
the two together; where they overlap, this one is cited from there.

Every claim below was verified against source at the time of writing, and the
performance numbers are **measured**, not estimated — see *How this was
verified* at the end.

---

## Resolved in this pass

### Correctness

**Cloud pull returned rows in undefined order, and screens read recency off
array position.** `pullState` issued ten `select('*')` queries with no
`.order()` anywhere in `src/lib/sync.ts`, and `mergeCloud`'s `union()` appends
cloud rows verbatim. Postgres promises no ordering without an `ORDER BY`, and
every `pushState` upsert rewrites its row — so results genuinely scramble as an
account is used. Locally this was invisible, because `addWorkoutLog` and friends
prepend; it only appeared **after a cross-device restore**, i.e. precisely for
paying multi-device users.

Fixed at both ends: an explicit `.order()` on every list query in `pullState`,
plus a sort at each consumer that had been trusting arrival order —
`Dashboard.tsx` and `OffSeasonDashboard.tsx` ("Recent Sessions"),
`CoachDashboard.tsx`'s local-fighter sparring list (the *same file* already
sorted correctly in its cloud branch), and `AIInsights.tsx`'s conditioning
slice, which had been feeding an arbitrary six tests into an analysis the
subscription paid for.

**The order direction is not uniform, and getting that wrong is its own bug.**
The first version of this fix applied `{ ascending: false }` to every table,
including camps. That is wrong, because the local conventions differ:

| collection | local insert | newest is |
|---|---|---|
| `camps` | `CREATE_CAMP` **appends** | **last** |
| everything else | `add*` **prepends** | **first** |

`camps[camps.length - 1]` is the app-wide idiom for "the current camp" — used
by `mergeCloud`'s active-camp fallback, `deleteCamp`'s promotion, and
`CoachDashboard` twice. Sorting camps newest-first silently made all four pick
the *oldest* camp, so a restored multi-camp account would open on a finished
camp and regenerate the schedule for it. Caught in review on PR #85; camps are
now pulled ascending, everything else descending, and both directions are
pinned by tests.

**`loadState` shallow-merged a persisted document over the defaults.** A
top-level spread replaces each nested slice wholesale, so a document written
before a key was added to `gamification` / `dashboardPrefs` / `subscription`
kept its old shape and the new key stayed `undefined` after upgrade —
`gam.challenges.filter(...)` in `ProgressWidget` throws on a store that merely
predates challenges. Now merged one level deeper, and deliberately no deeper:
`belt` and `streak` are recomputed from raw logs by the boot-time
`RECOMPUTE_GAMIFICATION`, so they only need to *exist*; the slices that do not
self-heal all sit at that level. `weightUnit` stays absent from the defaults so
"never chosen" survives, which is what lets `mergeCloud` restore the account's
synced choice on a new device.

**A push dropped during an in-flight sync was never retried.** `syncNow`
returned early when one was already running, and the debounce timer that fired
had already been cleared — so edits made during a slow upload waited for the
next *unrelated* state change. Now a skipped run sets a pending flag and the
in-flight run loops once more when it settles. It loops rather than recurses (a
burst of edits costs one extra push, not a stack frame each), and it stops on
error rather than hammering a failing server — the next change's debounce is the
retry.

**`AdBanner` could render a permanently blank 50px bar.** The AdSense loader
`<script>` in `index.html` is commented out, so `window.adsbygoogle` never
exists and the component's `push({})` only appended to a plain array. With both
`VITE_ADSENSE_*` env vars set, free users got a dead 50px strip above the tab
bar — real layout cost, no ad. The banner now also requires the library to
actually be on the page; uncommenting the loader is all that is needed to turn
it back on.

### Performance

**Every dispatch synchronously serialized the entire account document.**
`saveState` runs `JSON.stringify` + `localStorage.setItem` over *all* camps,
logs, weigh-ins, nutrition, HRV, fight results and gamification — and it ran on
every state change. Writes are now coalesced (500 ms) and handed to an idle
slot, with flushes on `visibilitychange`/`pagehide` and provider unmount so
nothing is lost.

Measured on the demo account, eight rapid taps of the nutrition quick-add
button:

| | writes to `fightcamp_app` | bytes serialized |
|---|---|---|
| before | 8 | 227,731 |
| after | 1 | 28,449 |

Final persisted state is identical (128 oz). A real mid-camp account is larger
than the demo seed, so the absolute saving scales with it.

**The round timer wrote to `localStorage` once per second.** The persist effect
listed `timeLeft` in its dependencies, so a 12-round boxing session performed
roughly 2,900 blocking writes to save a value already implied by
`phaseDeadline` — which is an absolute wall-clock instant that only moves at a
phase transition. `timeLeft` is now out of the dependency array; restore
recomputes the remaining seconds via `fastForward`, exactly as before.

Worth recording *why* this is safe rather than just asserting it: the only
reader of `timeLeft` there is `pausedTimeLeft`, used solely when `!isRunning` —
a state in which `timeLeft` cannot change. `eslint-plugin-react-hooks`
independently confirmed the fix: two long-standing
`react-hooks/set-state-in-effect` suppressions in the same file became
*unused* once the dependency was dropped, because the write cascade they were
suppressing no longer exists. Both directives were removed.

**`computeReadiness` ran unmemoized on every Dashboard render.** It filters and
sorts five collections and walks every camp workout, and `Dashboard` re-renders
on *any* dispatch — including the hourly gamification recompute and session
toggles, neither of which is an input to the score. Now memoized on the slices
it actually reads (not on `state`, whose identity changes on every dispatch and
would defeat the memo), plus a day key so the elapsed-time terms cannot go stale
on a dashboard left open overnight.

**`TimerContext` handed out a fresh object on every tick.** `{ signal,
setSignal }` as an object literal meant every consumer re-rendered once a second
for the length of a session — including the *producer*, `useRoundTimer`, which
only ever needs the setter and was being re-rendered by its own writes. Split
into a signal context and a setter context; the setter is a `useState` setter
and therefore stable, so writers now subscribe to nothing.

### Design

**Inter is now actually loaded.** `index.css` has always named `'Inter'` as its
first font family and nothing ever loaded it — `@fontsource/inter` was a
dependency imported nowhere, so the app silently rendered in `system-ui` on
every platform. Now imported in `main.tsx`: latin subset only, and only the five
weights Tailwind utilities request in `src/` (400, 500, 600, 700, 900 — 800 is
deliberately absent, nothing uses it). ~120 KB of woff2.

This is a **visual change on every screen**, not a cleanup. `font-display: swap`
means text is never invisible. The `woff2` files were also added to the PWA
precache glob — without that, an installed PWA opened offline (a gym with no
signal, i.e. the actual use case) would fall back to `system-ui` and reflow on
every cold start. `.woff` is deliberately excluded: it exists only as a fallback
for browsers predating woff2, and no browser fetches both.

### Test coverage

**The three highest-risk modules had no tests; they do now.** Coverage went from
40 tests across 8 files to **126 across 13** (including the adherence and
reducer-purity suites added in the follow-up pass below), targeting the code most
able to destroy user data rather than the code easiest to test:

- **`tests/sync.test.ts` (18)** — `mergeCloud`'s documented edge cases, each
  previously guaranteed only by a comment: restore-of-never-seen rows,
  local-wins-on-conflict, *don't* resurrect a row deleted here
  (`previouslySynced`), *do* remove a row tombstoned elsewhere, camp-keyed
  metadata filtering on both sides, exact camp-id prefix matching (`camp-1` vs
  `camp-10`), active-camp promotion, per-key `dashboardPrefs` merge, and the
  invariant that subscription is never pulled. Plus `pullState`'s ORDER BY
  contract, asserted against a mocked query builder.
- **`tests/storage.test.ts` (13)** — the `deleteCamp` cascade across all nine
  camp-scoped collections plus the camp-keyed maps and game plan, prefix
  exactness, active-camp promotion, and the `loadState` upgrade path.
- **`tests/gamification.test.ts` (28)** — streak counting, the 48-hour grace
  window and expiry, both belt promotion paths and the half-credit rule for a
  completed camp with no win, PR detection including the case where deleting a
  log must *lower* a stale record, and weekly challenge rotation, determinism,
  scoring and history freezing.

The two regression tests were checked by falsification — each was confirmed to
**fail** with its bug reintroduced and pass with the fix, so neither is a test
that merely describes current behaviour.

## Resolved in a follow-up pass

Everything the "still open" list carried has since been closed.

### The reducer is now pure

`baseReducer` called `saveSubscription()`, `clearIdMap()`,
`clearFightCampLocalData()` and `requestLocalSignOut()` — none of which are
state transitions. `StrictMode` invokes reducers twice per dispatch in
development precisely to surface this, so every wipe and sign-out request fired
twice.

Those commands moved into a `dispatch` wrapper in `AppProvider`, which runs them
exactly once per dispatch in both development and production; cached entitlement
now follows `state.subscription` from an effect. `tests/reducer.test.ts` pins the
invariant directly — the reducer writes nothing to `localStorage`, dispatches no
window events, is idempotent under a double invoke, and does not mutate its
input. Confirmed by falsification: putting `saveSubscription` back in the reducer
fails the suite.

The wrapper also drops any coalesced `saveState` write before wiping. A queued
write holds the state being erased, and letting it land afterwards would write it
straight back.

### One definition of adherence

Six independent implementations, not the four originally counted — `WeeklyPlanner`,
`ProgressCharts` and `AIInsights` each rebuilt the same key logic, and the rest
disagreed outright. `src/utils/adherence.ts` is now the single source, and it
fixed two real defects rather than just deduplicating:

- **Dashboard and OffSeasonDashboard counted "done" with a prefix scan** over
  `completedSessions`, which also counts ticks whose session no longer exists.
  The schedule is regenerated on every camp edit, so shrinking a week orphans
  `true` entries — the dashboard could render **"7/5 sessions this week"**.
  Scoring only keys the current schedule generates makes `done <= planned` hold
  by construction.
- **OffSeasonDashboard excluded `type === 'rest'` sessions from the denominator**
  while the key builder still numbered them, so its planned count was too small
  on top of the above.

`campKpis.adherence` changed meaning, deliberately: it measured **logged workouts
÷ a `campWeeks * 4.5` estimate** while its own docstring and every label
rendering it said "schedule adherence". It now measures what it claims. It is
also `number | null`, because "no schedule to score against" is not "you missed
everything" — `factorTuner` moves readiness weights off this value and must not
tune on noise, and `fightAnalysis` must not invent a missed-sessions finding.
`FightBreakdown` renders the null case as an em dash, matching its own no-data
convention.

**Worth knowing before release:** a fighter who logged workouts but never ticked
the planner will now see a lower camp-comparison adherence than before, because
the number finally reflects plan adherence rather than volume. That is the
correct reading of the label, but it is a visible change to a rendered KPI. The
natural follow-up is to auto-tick a planned session when a matching workout is
logged — `WeeklyPlanner` already does that lookup in reverse.

### Smaller items

- `flash()` now tracks its 600 ms timer and clears it on unmount, and blanks the
  overlay on the way out — leaving it to fire would repaint a full-screen colour
  wash over whatever replaced the timer view.
- `defaultState` was deleted rather than frozen. Its last consumer (`demoSeed`)
  now calls `createDefaultState()`, so the shared mutable singleton is gone
  instead of merely guarded.
- `.input`'s placeholder moved to `gray-450`, the token the contrast pass applied
  to the other 121 sites.

## What is working well

Worth recording, so a future audit does not "fix" it:

- Route-level `lazy()` splitting is thorough, and the `manualChunks` reasoning
  in `vite.config.ts` is correct and unusually well argued — naming a chunk
  puts it on the critical path, which is exactly why `recharts` is left unnamed.
- Sync dirty-tracking via per-row FNV-1a hashes, with hashes staged per table
  and committed only after that table's write lands, is a genuinely good design.
- The entitlement path is properly server-authoritative: client-synced
  `user_state` is never consulted for authorization, quota is enforced
  atomically in Postgres, and the RevenueCat webhook's secret comparison is
  timing-safe.
- The audio limiter `WeakMap` in `useRoundTimer.ts` fixed a real leak
  (~40 live compressors per session) and should stay.

## How this was verified

- `npm run quality` — `lint && test && test:security && typecheck:functions &&
  build` — green. Lint is at its pre-existing 5-warning baseline (confirmed by
  diffing warnings against a stashed tree); 126/126 tests pass.
- **Every regression test was falsified before being trusted**: the camp-order
  test fails with `{ ascending: false }` restored, the `loadState` tests fail
  with the shallow spread restored, and the reducer-purity test fails with
  `saveSubscription` put back inside the reducer.
- **The adherence change was checked in the running app**, not just in unit
  tests: Playwright drove the demo account through planner, progress, nutrition,
  camp history and timer, and asserted no rendered `done/planned` pair violates
  `done <= planned`. Planner and dashboard now report the same figure (`0/8`),
  which they did not before.
- **Write-count measurements** were taken with Playwright against
  `npm run preview`, wrapping `Storage.prototype.setItem` and driving eight real
  taps, run once on a stashed pre-fix build and once after. The table above is
  those two runs.
- **Deferred-write safety** was verified separately: tap, read mid-debounce
  (value correctly not yet persisted), dispatch `visibilitychange` → `hidden`,
  read again (value durable). Backgrounding cannot lose an edit.
- `npm run screenshots` regenerated all 14 App Store captures and
  `npm run verify:appstore` passes on both size classes — this is also the
  visual check on the Inter change, since the harness captures the app UI with
  its real fonts. (`verify:appstore` still reports the pre-existing missing app
  preview video, which is out of scope here.)
- Font output inspected in `dist/`: 5 `@font-face` rules, latin-only, 5 woff2
  files precached, no `.woff` in the service worker.

*Findings that belong to `docs/ux-audit.md` were left there rather than
restated. Where this pass fixed something that document had described, it is
noted above rather than silently marked resolved in both places.*
